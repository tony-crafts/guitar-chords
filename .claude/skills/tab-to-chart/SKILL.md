# TAB 영상 → 코드 차트

입력: `$ARGUMENTS` — 영상 경로와 대상 곡 페이지(없으면 새 곡).

## 1. 페이지 추출 (스크립트)

```bash
scripts/tab-pages.py "<영상>" "<스크래치폴더>/tab" [--bpm <곡 BPM>]
```

- 기존 곡이면 페이지 파일의 `bpm`을 `--bpm`으로 넘긴다(한 페이지 = 4마디 길이 계산).
- TAB 영역이 화면 하단이 아니면 `--crop y0:y1`(0~1 비율)을 조정한다. 먼저 프레임 1장을 뽑아 위치를 확인할 것.
- 출력 `g0.jpg, g1.jpg …`(3페이지씩 세로 묶음)를 **전부** Read로 본다. 건너뛰지 말 것.
- `←` 표시가 붙은 페이지는 반드시 마디 수를 직접 센다:
  - `마디 수 직접 확인` — 한 화면에 5마디, 마지막 짧은 페이지, 타이틀 화면 등.
  - `같은 화면 N회 반복으로 추정` — 반복 페이지는 화면 변화가 거의 없어 길이로 나눈 것. 반복 횟수가 곡 구조와 맞는지 확인.
- 템포로만 페이지 시각을 계산하지 말 것 — 5마디 페이지 하나로 뒤가 전부 밀린다(용의자에서 실제 발생).

## 2. 판독 → 마디 목록

페이지마다 마디 단위로 적는다: 코드 이름(표기 그대로, 예 `Db5`, `Dbsus4`, `Adim7`), 코드가 바뀌는 박, 주법 단서.

- 코드 위치 → 박: 마디 폭을 4등분해 코드 이름 x좌표로 판단.
- 주법 단서: 단음 리프 / 8비트 스트로크 / 온음표·타이(한 번 치고 링 = 원샷 ◇) / X(뮤트) / 벤딩(½, full) / 당김(뒷박에서 코드 진입).

## 3. 차트 데이터 반영

song-core 스키마는 `chords/song-core.js` 맨 위 주석이 정본. 요점:

- 마디 토큰: `'Gb'` 단일 · `'Gb,F'` 반반 · `'Db,Dbsus4,Db'` 3분할 · `'Db^끝'` 마커 · 끝에 `*` = 원샷 ◇
- 반 마디보다 잘게 나뉜 리듬(2박 뒷박 당김 등)은 토큰으로 표현 불가 → 가장 가까운 분할로 두고 섹션 `note`에 적는다.
- 한 row = 화면의 한 줄. 5마디 페이지는 5칸 row로 그대로 둬도 된다(`--n`이 자동).
- **펼침(expanded) 뷰는 실제 연주 순서 그대로, 마디 1개 = `.bar` 1개** — 플레이어 싱크가 이 개수로 돈다. 반복을 접지 말 것.
- 컴팩트 뷰는 반복을 `repeat:'×N'`으로 접는다.
- 반복 블록은 파일 상단 변수(`RIFF`, `VERSE` …)로 두고 재사용.
- 새 코드가 생기면 `capoMap`과 `chordList`(원키/카포 둘 다)에 추가.
- 범례(legend)에 주법 표기 설명: 무표시 = 8비트 · ◇ = 원샷.
- 새 곡이면 `chords/suspect.html`을 복사해 시작하고 `index.html`에 `.song` 카드 추가(README "곡 추가").

기존 차트를 고칠 때는 **기존과 다른 점만 목록으로** 사용자에게 보고한다(섹션 반복 횟수, 마디 수, 총 마디 수 변화).

## 4. 확인

`.claude/launch.json`의 `static` 서버로 페이지를 띄워(`preview_start` name=static):

```js
Array.from(document.querySelectorAll('.view')).map(v => v.id + ':' + v.querySelectorAll('.bar').length)
```

- `viewF` 개수 = 판독한 총 마디 수와 일치해야 한다.
- 콘솔 에러 없음, 스크린샷으로 섹션·노트 확인.
- 마디 수가 바뀌면 사용자에게 t0(싱크) 재조정 필요하다고 알릴 것.
